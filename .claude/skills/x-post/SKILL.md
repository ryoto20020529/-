# X 投稿生成

企画担当(planning)→編集担当(editor)の流れで実行する。
**このスキルの目的は「一般論を絶対に出さないこと」。** 誰の体験でも書ける文章は失敗。社長本人の固有の工程・数字・失敗が入っていて初めて合格。

---

## STEP 0 — 必須の事前読み込み(飛ばすと一般論しか出ない。例外なし)

以下を**実際にReadしてから**書き始める。読まずに書くのは違反。
1. `docs/knowledge/コンセプト.md` — 発信軸・ターゲット・口調(一人称「僕」/ ですます / 絵文字1個まで / 煽らない)
2. `docs/knowledge/NGワード.md` — 禁止ワード・禁止表現
3. `docs/knowledge/伸び投稿DB.md` — 型とブクマ率の実データ、今週の最強の型
4. `docs/knowledge/投稿最適化.md` — SEO・インプレッション・クリック対策
5. `docs/research/viral-patterns.md` — 型の定義(フック/展開/CTAの構造)

---

## STEP 1 — 型を選ぶ

- DBの「今週の最強の型」を第一候補にする。データ不足時は `viral-patterns.md` から**発信軸との相性**で選ぶ。
- 選んだ理由を1行で言語化する(例:「工程公開型。DBでブクマ率最高かつ、AI活用の実演と相性が良いため」)。
- 3案すべてを同じ型にしない。**2案は主役の型、1案は別角度の対抗案**(質問・巻き込み型など)にして、社長が選べる幅を作る。

---

## STEP 2 — 素材(社長の固有体験)を確定する

- 指示に体験が含まれていればそれを使う。なければ直近の会話・作業ログ・`docs/tasks/board.md` から拾えるか探す。
- それでも無ければ社長に**選択肢形式で**素材を求める(「◯◯の件を素材にしていいですか?」)。オープンクエスチョン禁止。
- 素材には最低1つ、**固有の数字**を必ず含める(所要時間 / 費用 / 件数 / 変化率など)。数字が無い体験は「昨日の作業を分単位で」など具体化して補う。

---

## STEP 3 — フックを書く(全体の勝敗はここで決まる)

- タイムラインで見えるのは**最初の約40字**。この40字だけでスクロールを止める。
- 有効なフック公式(いずれか1つを選ぶ):
  - **数字先出し**:「30分・費用0円で、SNS運用を会社ごと自動化しました」
  - **逆説/常識否定**:「AIに投稿を作らせても伸びない。原因は設定1行でした」
  - **Before晒し**:「昨日まで投稿に1本30分かけていた僕が」
  - **問いかけ**:「SNS運用、どこまでAIに任せられると思いますか?」
- フックに**検索キーワード**(Claude Code / AI活用 / 生成AI / 自動化 のいずれか)を自然に含める(X内SEO)。
- フックのNG:「ヤバい」「神」「知らないと損」等(NGワード.md)。煽りは信頼を削る。

---

## STEP 4 — 本文を組む(選んだ型の構造に従う)

- 型ごとの展開は `viral-patterns.md` の定義に厳密に従う(例: 工程公開型 = 手順を①②③でそのまま見せる/隠さない/盛らない)。
- **2〜3行ごとに改行**。スマホでの視認性を最優先。長い塊は読まれない。
- 具体を書く。抽象語(「効率化」「便利」)は固有名詞・数字・実際の操作に置き換える。
- **本文に外部リンクを入れない**(リーチが大きく落ちる)。リンク・補足は STEP 6 のリプライに回す。
- 長さは内容次第で可変。ただし1ツイート完結なら**280字(weighted)以内**を厳守。長い話はスレッドにせず、1投稿1テーマに絞る方を優先する。

---

## STEP 5 — CTAを1つだけ置く

- 1投稿にCTAは1つ。複数混ぜると全部弱くなる。
- 型に合わせて選ぶ:手順・ノウハウ系→「保存推奨」でブクマを明示的に促す / 意見系→「あなたはどう?」でリプを促す。
- プロフィール誘導はCTAではなくSTEP 6のリプライと固定ポストで担う。

---

## STEP 6 — 投稿直後リプライ(導線)をセットで作る

- 本文にリンクを入れない代わりに、**投稿直後に社長がぶら下げる自己リプライ**を1本必ず用意する。
- ここに補足・リンク・「毎日公開します」等の継続予告・リプ誘発を置く。リプ欄が伸びるとプロフクリックが増える。

---

## STEP 7 — セルフチェック(1項目でもNGなら書き直す)

各案について機械的に確認する:
- [ ] NGワード.md の禁止語・禁止表現がゼロ
- [ ] 口調(僕 / ですます / 絵文字1個まで / 煽らない)に一致
- [ ] 固有の数字が1つ以上入っている(一般論回避の生命線)
- [ ] フック(先頭40字)だけでスクロールが止まるか声に出して確認
- [ ] 検索キーワードが前半にある
- [ ] 本文に外部リンクがない / CTAは1つ
- [ ] 280字(weighted)以内 — 全角=2, 半角=1で数える。判定は下記スクリプトで確認:
  `python3 scripts/post_to_x.py --dry-run "本文"`(weighted長を表示。投稿はしない)

---

## STEP 8 — 保存と提示

- `posts/drafts/YYYY-MM-DD.md` に保存。各案に「使った型 / 狙い / CTA / 推奨可否と理由」を付記。ファイル冒頭に最適化チェック結果も書く。
- 社長へ提示:**本文はコピペしやすいコードブロック**で、推奨案を先頭に理由付きで。投稿直後リプライも併せて提示する。投稿時間の推奨(朝7〜8時/昼12時台/夜21〜22時 JST)を添える。
- 投稿は社長が手動コピペで行う(課金ゼロ運用 — 2026-07-05社長決定。X APIは使わない)。「投稿した」の連絡を受けたら:
  1. 該当案を `posts/published/YYYY-MM-DD-slug.md` へ移動
  2. 24時間後に反応(表示数・ブクマ)を聞き、`docs/knowledge/伸び投稿DB.md` に記録するタスクを `board.md` に積む

---

## 下書きファイル形式
```
# YYYY-MM-DD 投稿案(型: ◯◯型)
最適化チェック: キーワード配置 / リンク無し / CTA1つ / 各案280字以内
## 案A(推奨: 理由)
---post---
(本文)
## 投稿直後リプライ
---post---
(リプ本文)
```
※ `scripts/post_to_x.py --file` は `---post---` 以降〜次の見出しまでを本文として読む。

## やってはいけないこと(即やり直し対象)
- 3ファイルを読まずに書く / 固有の数字が無い / 誰の体験でも成立する文章
- 本文にリンクを入れる / ハッシュタグ2個以上 / CTAが複数 / NGワード混入
- 社長の承認前に投稿する(このアカウントは手動投稿。APIは使わない)
