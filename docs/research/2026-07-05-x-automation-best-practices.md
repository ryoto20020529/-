# X(Twitter)自動運用ベストプラクティス調査(調査日: 2026-07-05)

担当: リサーチ

## 調査目的
Claude CodeによるX自動運用(バズ投稿の分析 → 投稿生成 → 定期自動投稿)の実現方法と制約を明らかにする。

## 事実(データ・観察)

### X APIの現状(2026年時点)
- **無料ティアは新規開発者向けには終了**(2026年2月)。新規は**従量課金(Pay-As-You-Go)**モデル。
- 従量課金の投稿コスト: **テキスト投稿 約$0.015/件、URL付き投稿 約$0.20/件**(2026年4月20日改定)。
- 2026年4月の改定で、**フォロー・いいね・引用の書き込みAPIはEnterprise専用**になった。セルフサーブ層でできる書き込みは実質「投稿(ポスト)」のみ。
- レート制限: 15分ローリングウィンドウ制。UIレベルでも全アカウント2,400投稿/日の上限。

### 自動化ルール(Xの利用規約)
- **ID/パスワードによるブラウザ自動ログイン・スクレイピングは利用規約違反**。アカウント凍結リスクが高い(特に新規デバイス+自動操作の組み合わせは即座にチャレンジ認証が発動する)。
- 自動化はX APIの開発者アカウント経由が唯一の正規ルート。
- 大量・無差別な自動投稿、トレンドの乗っ取り、重複コンテンツの反復投稿は自動化ポリシー違反。

### バズ投稿分析の制約
- 世界中の高インプレッション投稿を**APIで検索・取得するのは有料上位ティア**(検索エンドポイントは高額)。
- 現実的な代替手段:
  1. Web検索・公開ページ経由での事例研究(無料・本システムで採用)
  2. 参考にしたい投稿URLを社長が渡す → 構造分解して型化
  3. 自アカウントのアナリティクス(無料でエクスポート可)の振り返り

### Claude Code運用のベストプラクティス(事例調査より)
1. **「AI生成 → 人間承認 → 投稿」フローが企業運用の鉄則。** 完全無人投稿はブランド毀損事故(文脈読み違い・炎上)の主因。
2. APIキーは環境変数・シークレット管理。コードやリポジトリに直接書かない。
3. 投稿の型: **フック(1行目)→ ボディ → CTA** の3部構成。
4. 人間味の設計: 具体的エピソードを入れる、AIの定型句を禁止リスト化する。
5. 定期実行はスケジューラ(cron/トリガー)+ 下書きストック方式。ネタ切れ時に慌てて低品質投稿を出さない。

## 考察
- パスワードログインによる自動化は「作れるが、確実にアカウントを危険に晒す」選択肢であり、採用すべきでない。
- 従量課金なら1日1〜3投稿の運用で**月額コストは数十円〜数百円程度**。コスト面の障壁は低い。
- バズ分析はAPI検索を買うより、Web調査+型の蓄積(`docs/research/viral-patterns.md`)で十分機能する。

## 戦略・企画への示唆(3点以内)
1. **正規のX API(従量課金)+ 承認フロー付き自動投稿**が唯一の持続可能な構成。
2. バズ研究は「毎日の自動Web調査 → 型ストックに蓄積 → 企画・編集が型を再利用」のループで回す。
3. 投稿頻度は1日1〜2本から開始し、アナリティクスを見て増減する(量より継続)。
